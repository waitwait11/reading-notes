### 2. 语言模型演进：从 N-gram 到 Transformer

#### 2.1 统计语言模型与 N-gram

语言模型的根本任务是**计算一个词序列（即一个句子）出现的概率**。一个好的语言模型能够告诉我们什么样的句子是通顺的、自然的。

对于由词 w1,w2,⋯ ,wm*w*1,*w*2,⋯,*w**m* 构成的句子 S*S*，其概率可以通过**概率的链式法则**表示为：

P(S)=P(w1)⋅P(w2∣w1)⋅P(w3∣w1,w2)⋯P(wm∣w1,⋯ ,wm−1)*P*(*S*)=*P*(*w*1)⋅*P*(*w*2∣*w*1)⋅*P*(*w*3∣*w*1,*w*2)⋯*P*(*w**m*∣*w*1,⋯,*w**m*−1)

然而，直接计算这个公式几乎不可能，因为像 P(wm∣w1,⋯ ,wm−1)*P*(*w**m*∣*w*1,⋯,*w**m*−1) 这样的条件概率太难从语料库中估计，词序列可能从未在训练数据中出现过。

**马尔可夫假设**的核心思想是：不必回溯一个词的全部历史，可以近似地认为，一个词的出现概率只与它前面有限的 n−1*n*−1 个词有关。基于这个假设建立的语言模型称为 **N-gram 模型**。

- **Bigram (N=2)**：P(wi∣w1,⋯ ,wi−1)≈P(wi∣wi−1)*P*(*w**i*∣*w*1,⋯,*w**i*−1)≈*P*(*w**i*∣*w**i*−1)
- **Trigram (N=3)**：P(wi∣w1,⋯ ,wi−1)≈P(wi∣wi−2,wi−1)*P*(*w**i*∣*w*1,⋯,*w**i*−1)≈*P*(*w**i*∣*w**i*−2,*w**i*−1)

概率通过**最大似然估计（MLE）**计算：最可能出现的，就是在数据中看到次数最多的。

#### 2.2 神经网络语言模型与词嵌入

神经网络语言模型引入了**词嵌入（Word Embedding）**：将离散的词映射为连续的高维向量，语义相似的词在向量空间中距离更近。这解决了 N-gram 的泛化问题——即使两个词在语料库中从未出现在相同上下文中，只要语义相近，模型也能进行合理预测。

但前馈神经网络语言模型仍有**固定上下文窗口**的限制：它只能看到前 n−1*n*−1 个词，再早的历史信息就被丢弃了。

#### 2.3 RNN 与 LSTM：引入记忆能力

**循环神经网络（RNN）** 的核心思想是为网络增加“记忆”能力。RNN 引入了一个**隐藏状态（hidden state）**向量，可以理解为网络的短期记忆。在处理序列的每一步，网络读取当前输入词，结合上一刻的记忆，生成新的记忆传递给下一刻。

然而，标准 RNN 存在**长期依赖问题**：当序列很长时，梯度在反向传播过程中会快速趋向于零（**梯度消失**）或变得极大（**梯度爆炸**）。梯度消失使得模型无法有效学习到序列早期信息对后期输出的影响。

**LSTM** 通过引入**细胞状态（Cell State）**和**门控机制（Gating Mechanism）**来解决这一问题：

- **遗忘门**：决定从上一时刻的细胞状态中丢弃哪些信息
- **输入门**：决定将当前输入中的哪些新信息存入细胞状态
- **输出门**：决定根据当前的细胞状态，输出哪些信息到隐藏状态

#### 2.4 Transformer 架构解析

RNN 及 LSTM 虽然在一定程度上解决了长距离依赖问题，但其**循环的计算方式**带来了新的瓶颈：必须按顺序处理数据，第 t*t* 个时间步的计算必须等待第 t−1*t*−1 个时间步完成后才能开始，无法进行大规模并行计算。

Transformer 在 2017 年由谷歌团队提出，**完全抛弃了循环结构**，转而完全依赖**注意力（Attention）**机制来捕捉序列内的依赖关系，从而实现了真正意义上的并行计算。

**Encoder-Decoder 整体结构**：

- **编码器**：任务是“理解”输入的整个句子，为每个词元生成一个富含上下文信息的向量表示
- **解码器**：任务是“生成”目标句子，参考自己已经生成的前文，并“咨询”编码器的理解结果来生成下一个词

**自注意力机制**是 Transformer 的核心。它为每个词元生成三个向量：**查询（Q）**、**键（K）**、**值（V）**。通过计算查询与所有键的相似度，得到注意力权重，再对值进行加权求和。其公式为：

Attention(Q,K,V)=softmax(QKTdk)VAttention(*Q*,*K*,*V*)=softmax(*d**k**Q**K**T*)*V*

**多头注意力**并行执行多次自注意力，让模型能够同时关注不同位置的不同表示子空间。

**前馈网络（FFN）** 对每个位置的表示进行非线性变换，采用“先扩大再缩小”的模式（dff=4×dmodel*d**ff*=4×*d**m**o**d**e**l*），有助于模型学习更丰富的特征表示。

**残差连接与层归一化**：每个子模块都被一个 Add & Norm 操作包裹。残差连接解决了深度神经网络中的**梯度消失**问题，层归一化解决了**内部协变量偏移**问题，两者共同保证了 Transformer 能够稳定训练。

**位置编码**：自注意力本身不包含任何关于词元顺序或位置的信息——“agent learns”和“learns agent”在自注意力看来完全等价。位置编码为每个词元的嵌入向量额外加上一个代表绝对位置和相对位置信息的“位置向量”，使用正弦和余弦函数生成。

### 3. 与大语言模型交互

#### 3.1 指令调优

GPT-3 等早期模型主要是“文本补全”模型，擅长根据前面的文本续写，但不一定能很好地理解并执行人类的指令。**指令调优（Instruction Tuning）**使用大量“指令-回答”格式的数据对预训练模型进行进一步训练，使模型能更好地理解并遵循用户的指令。ChatGPT、DeepSeek、Qwen 等模型都是经过指令调优的版本。

#### 3.2 基础提示技巧

- **角色扮演**：赋予模型特定角色，引导回答风格和知识范围
- **上下文示例**：通过提供输入输出示例，教会模型如何处理特定格式或风格的任务

#### 3.3 思维链（Chain-of-Thought, CoT）

对于需要逻辑推理、计算或多步骤思考的复杂问题，直接让模型给出答案往往容易出错。CoT 通过引导模型“一步一步地思考”，显著提升了复杂任务上的推理能力。实现 CoT 的关键是在提示中加入“请逐步思考”或“Let's think step by step”等引导语。

#### 3.4 文本分词

计算机只能理解数字，因此在将文本喂给大语言模型之前，必须先将其转换成数字格式，这个过程叫做**分词（Tokenization）**。分词器将原始文本切分成一个个最小的单元，称为**词元（Token）**。

**为何需要子词分词**：

- **按词分词**：面临**词表爆炸**和**未登录词（OOV）**问题——无法处理未在词表中出现过的词
- **按字符分词**：词表小，但单个字符缺乏语义信息

**BPE（Byte Pair Encoding）**算法通过迭代合并频率最高的相邻字符对，在词表大小和语义保留之间取得平衡，是主流大语言模型广泛采用的分词方案。

### 4. 模型选型与部署

#### 4.1 选型关键考量

选择语言模型并非简单地追求“最大、最强”，而是需要在以下维度进行权衡：

- **性能与能力**：不同模型擅长的任务不同
- **成本**：闭源按 Token 计费，开源需硬件和运维投入
- **速度（延迟）**：实时交互场景对响应速度要求高
- **上下文窗口**：长文档分析、长期对话记忆需要大窗口
- **部署方式**：API 调用便捷但数据需发送第三方，本地部署隐私可控但技术要求高
- **生态与工具链**：主流模型拥有更丰富的社区支持和兼容框架
- **可微调性与定制化**：开源模型在此方面提供更大灵活性
- **安全性与伦理**：需考虑偏见、毒性、幻觉等方面的表现

#### 4.2 闭源与开源模型概览

- **OpenAI GPT 系列**：从 GPT-3 到 ChatGPT 再到 GPT-4、GPT-5，持续引领行业发展
- **Google Gemini 系列**：原生多模态，超长上下文窗口

## 二、课后习题与解答

### 习题 1：语言模型演进

#### 1.1 计算句子“agent works”在 Bigram 模型下的概率

**迷你语料库**：`datawhale agent learns datawhale agent works`

**分词**：`['datawhale', 'agent', 'learns', 'datawhale', 'agent', 'works']`，总词数 N=6*N*=6

**第一步：计算 P(agent)\*P\*(agent)**

agent 出现次数为 2，P(agent)=26≈0.333*P*(agent)=62≈0.333

**第二步：计算 P(works∣agent)\*P\*(works∣agent)**

Bigram 对：`(datawhale, agent)`、`(agent, learns)`、`(learns, datawhale)`、`(datawhale, agent)`、`(agent, works)`

`(agent, works)` 出现 1 次，P(works∣agent)=12=0.5*P*(works∣agent)=21=0.5

**第三步：计算句子概率**

P(agent works)=P(agent)×P(works∣agent)=0.333×0.5≈0.167*P*(agent works)=*P*(agent)×*P*(works∣agent)=0.333×0.5≈0.167

**完整代码**：

```python
import collections

corpus = "datawhale agent learns datawhale agent works"
tokens = corpus.split()
total_tokens = len(tokens)

# 第一步：P(agent)
count_agent = tokens.count('agent')
p_agent = count_agent / total_tokens

# 第二步：P(works|agent)
bigrams = list(zip(tokens, tokens[1:]))
bigram_counts = collections.Counter(bigrams)
count_agent_works = bigram_counts[('agent', 'works')]
p_works_given_agent = count_agent_works / count_agent

# 第三步：P(agent works)
p_sentence = p_agent * p_works_given_agent
print(f"P(agent) = {p_agent:.3f}")
print(f"P(works|agent) = {p_works_given_agent:.3f}")
print(f"P(agent works) = {p_sentence:.3f}")
```



输出结果：`P(agent) = 0.333`，`P(works|agent) = 0.500`，`P(agent works) = 0.167`

#### 1.2 马尔可夫假设的含义与 N-gram 局限

**马尔可夫假设**：一个词的出现仅依赖于前面出现的有限个词，而非全部历史。

**N-gram 模型的根本性局限**：

1. **上下文长度固定**：只能考虑前 n−1*n*−1 个词，无法捕捉更长距离的依赖关系
2. **数据稀疏性**：未出现过的词序列概率估计为 0，导致模型无法处理新组合
3. **泛化能力差**：无法理解语义关系——“agent”和“robot”在语义上相近，但 N-gram 视其为完全不同的符号

#### 1.3 神经网络语言模型与 Transformer 的改进

**RNN/LSTM 的改进**：

- 引入**隐藏状态**传递序列信息，克服固定上下文窗口的限制
- **词嵌入**解决离散符号的泛化问题，语义相似的词在向量空间中靠近
- LSTM 通过**门控机制**缓解梯度消失问题
- 但仍存在**串行计算**的效率瓶颈

**Transformer 的改进**：

- **自注意力机制**一次性计算序列中所有词对的关系，既突破了固定窗口，又避免了梯度问题
- **并行计算**：所有位置的 QKV 可以同时生成，注意力得分通过矩阵运算并行计算
- **多头注意力**捕捉多种维度的关系
- **位置编码**显式表示词序信息

### 习题 2：Transformer 架构

#### 2.1 自注意力机制的核心思想

自注意力机制的核心思想是：**学习每个词与所在句子中所有词的相关程度**。每个词通过三个可学习向量——**查询（Q）**、**键（K）**、**值（V）**——与序列中所有词计算关联权重，然后对值进行加权求和，得到该词的上下文感知表示。

#### 2.2 为什么 Transformer 能并行而 RNN 必须串行

**Transformer 能并行的原因**：没有 RNN 的循环依赖，所有词的 Q、K、V 可以同时生成，注意力得分通过矩阵运算一次性并行计算。

**RNN 必须串行的原因**：第 t*t* 个时间步的计算必须等待第 t−1*t*−1 个时间步完成，因为隐藏状态的传递是顺序依赖的。

**位置编码的作用**：RNN 通过串行处理自动了解词的位置关系，而 Transformer 的自注意力机制本身不感知词的顺序，需要引入位置编码来显式表示位置关系。没有位置编码，“agent learns”和“learns agent”对 Transformer 来说完全等价。

#### 2.3 Decoder-Only 与 Encoder-Decoder 架构的区别

**Encoder-Decoder 架构**：包含编码器和解码器两部分。编码器理解输入，解码器生成输出。适用于机器翻译等需要“理解输入再生成输出”的任务。

**Decoder-Only 架构**：仅保留解码器部分，通过**自回归**模式生成文本——预测下一个词，将生成的词加入输入，重复此过程。关键创新是**掩码自注意力**，防止模型“偷看”未来的词。

**为什么主流 LLM 采用 Decoder-Only**：

1. 大语言模型的核心任务是**预测下一个词**，Decoder 正是做这个的
2. **结构更简单**，训练成本更低
3. **自回归生成能力突出**，天然适配所有生成式任务
4. 不需要人工标注数据，可利用海量无标注文本进行预训练

### 习题 3：文本分词

**为什么不能直接以“字符”或“单词”作为输入单元**：

- **按词分词**：词汇量巨大导致**词表爆炸**；新词、组合词无法在词表中找到，产生**未登录词（OOV）**问题
- **按字符分词**：词表小，但单个字符缺乏语义信息，序列长度过长

**BPE 算法解决了什么问题**：

BPE 通过迭代合并频率最高的相邻字符对，构建子词词表。它**兼顾词表大小和语义保留**——未见过的词可以拆解为已知子词，保留一定语义信息。例如“DatawhaleAgent”可以被拆解为“Data”、“whale”、“Agent”等已知子词。

### 习题 4：本地部署实践与分析

#### 4.1 部署流程关键步骤

1. 选择轻量级开源模型（如 Qwen3-0.6B）
2. 安装推理框架（如 Ollama、vLLM、llama.cpp）
3. 下载模型权重
4. 配置推理参数（温度、top_p、max_tokens 等）
5. 启动推理服务，通过 API 或命令行交互

#### 4.2 提示策略对比

| 策略                 | 说明                     | 适用场景                       |
| :------------------- | :----------------------- | :----------------------------- |
| **Zero-shot**        | 直接给出指令，不提供示例 | 简单任务，模型已有足够先验知识 |
| **Few-shot**         | 提供少量输入输出示例     | 需要特定格式或风格的任务       |
| **Chain-of-Thought** | 引导模型逐步推理         | 复杂逻辑推理、数学计算         |

以情感分析为例，Zero-shot 可能直接输出“负面”，而 CoT 会先找出关键词“糟糕”、“浪费钱”，再推断情感倾向，对于复杂或隐含情感的文本，CoT 能提高分析质量和可信度。

#### 4.3 闭源模型 vs 开源模型对比

| 维度       | 闭源模型（如 GPT-4、Gemini）                          | 开源模型（如 LLaMA、Qwen）                                   |
| :--------- | :---------------------------------------------------- | :----------------------------------------------------------- |
| **性能**   | 通常领先，尤其在复杂推理和指令遵循上                  | 第一梯队已接近顶级闭源模型，中等规模模型足够应对许多任务     |
| **成本**   | API 调用按 Token 计费，长期使用成本高，但无需硬件投入 | 一次部署，无限使用。需要自有硬件，初期投入，长期成本可能更低 |
| **可控性** | 低，只能通过 API 交互                                 | 极高，可完全控制模型权重、微调、裁剪、量化                   |
| **隐私**   | 数据需发送至厂商服务器，存在隐私泄露风险              | 数据完全本地处理，隐私安全有保障                             |
| **定制化** | 有限，主要依赖提示工程                                | 可深度定制，可用领域数据继续训练                             |

#### 4.4 企业级客服智能体的模型选择

**建议选择开源模型**，关键考虑因素：

1. **数据隐私与安全**：客服涉及用户订单、个人信息等敏感数据，必须本地部署确保数据不出域
2. **成本可控**：企业级客服请求量大，使用闭源 API 长期成本不可控
3. **定制化需求**：需要将企业知识库、产品文档注入模型，开源模型支持 RAG 和微调
4. **可控性与可靠性**：需要保证服务稳定，避免因闭源 API 服务波动影响业务
5. **性能要求**：客服任务以信息检索、多轮对话、意图分类为主，当前优秀开源模型已能很好胜任

**综合建议**：选择一款性能足够、中文能力强的开源模型（如 Qwen）进行本地化部署，结合 RAG 接入企业知识库，并通过微调优化对话风格。

### 习题 5：模型幻觉

#### 5.1 缓解幻觉的方法（以 RAG 为例）

**检索增强生成（RAG）** 的工作原理：

1. **检索**：当用户提问时，系统首先从外部可信知识库（如企业文档、维基百科、专业数据库）中检索与问题相关的文档或片段
2. **增强**：将检索到的相关文本作为“证据”或“上下文”，与用户的原始问题一起拼接，构成信息丰富的提示
3. **生成**：将增强后的提示输入大语言模型，要求它基于提供的上下文生成答案，引导模型“引用”证据，减少凭空编造

**适用场景**：

- 需要事实准确性的领域：客服、技术支持、法律、医疗问答
- 回答需要最新信息的问题：知识库可随时更新，弥补模型静态知识的不足
- 涉及私有或特定领域知识的任务：企业内部知识查询、产品文档问答

#### 5.2 其他缓解幻觉的方法

1. **推理时自我验证（Self-Verification）**：让模型在生成答案后自行检查逻辑一致性和事实准确性，发现矛盾则重新生成
2. **多路径推理与投票**：让模型通过多条推理路径生成多个答案，选择最一致的输出
3. **工具调用验证**：让模型调用外部工具（如计算器、搜索引擎）验证生成内容中的事实性陈述
4. **知识图谱约束**：利用结构化知识图谱对生成内容进行约束和校验

### 习题 6：论文辅助阅读智能体设计

#### 6.1 基座模型选择

建议选择**长上下文窗口的开源模型**（如 Qwen2.5-72B 或 LLaMA 3.1），理由：

- 学术论文通常篇幅较长（数万字），需要大上下文窗口
- 开源模型支持本地部署，方便处理未公开的论文数据
- 可通过微调适配学术领域术语

#### 6.2 长文本处理策略

- **分块+摘要**：将论文按章节分块，逐块生成摘要，再汇总
- **滑动窗口+记忆**：使用滑动窗口处理超长文本，配合外部记忆模块存储关键信息
- **RAG 检索**：将论文向量化存入向量数据库，根据用户问题检索相关段落

#### 6.3 准确性保障设计

- 引用原文段落，标注信息来源
- 对关键结论进行交叉验证
- 提供原文链接，方便用户核实
- 设置置信度评分，低置信度内容明确标注

## 三、个人思考

第三章的核心价值在于**建立了从“词序列概率”到“自注意力并行计算”的连贯知识链条**。最深刻的启示是：技术演进往往不是“凭空创造”，而是针对前人局限的“精准改进”——N-gram 解决“如何计算句子概率”，但受限于数据稀疏；神经网络引入词嵌入解决泛化，但受限于固定窗口；RNN 引入记忆机制，但受限于梯度消失和串行计算；Transformer 用自注意力彻底解决了并行和长距离依赖问题，但代价是内存随序列长度平方增长。

理解每种模型的设计动机比记住其公式更重要。对于智能体开发而言，LLM 是智能体的“大脑”，理解其底层原理——特别是自注意力的工作机制、位置编码的必要性、以及 Decoder-Only 架构的生成方式——是设计高效智能体系统的基础。同时，模型幻觉、上下文窗口限制、推理成本等问题，也直接影响了智能体架构的设计决策（如是否需要 RAG、如何管理记忆、如何选择模型）。
